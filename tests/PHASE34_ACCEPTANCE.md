Local tests cover migration reruns, role/RLS boundaries, invitations, upload state, request quotas, stable Trip Check decisions, AI response validation, automatic city zones, encrypted IndexedDB and a browser offline reader. These do not prove that the live SQL, OAuth, Storage or paid provider configuration is correct.

1. Apply 005–008 in order. Create a Tokyo → Sydney trip from city results. Confirm no time-zone field appears anywhere; local departure and arrival zones differ automatically. Add a linked plan, change its destination city, and confirm inferred zones follow while independently selected cities retain their zone. Verify existing trips and legacy aliases still load.
2. Save a manual idea; verify it is unscheduled. Request Sample Mode suggestions: cards must say mock/sample, not claim researched facts. Approve one into Ideas; explicitly schedule a day/time/duration. It becomes planned, never confirmed. Repeat approval through the API: only one plan exists.
3. Create a checkout-exclusive stay gap and an unsaved destination journey. Run Trip Check: every finding distinguishes saved evidence from uncertainty. Mark handled/snoozed, rerun, and confirm decisions persist. Resolve all findings; the last successful run should still be visible.
4. With paid keys absent, maps/Places/live AI explain their availability honestly. If keys are supplied, use restricted keys and provider-console quotas. Check real Places results, attribution/retrieval time, map/list selection and Google links. Save only a place ID plus personal label/notes; load fresh details explicitly. Verify no results or budgets are fabricated. Inspect that server keys never appear in browser bundles or responses.
5. Owner creates an invitation for a second account. A third/different or unverified email cannot preview/accept. Accept as the intended Google account; test expiry/revocation and repeated acceptance. Change editor to viewer: shared data still loads but all shared mutations fail through both UI and direct REST/RPC. Only owner changes trip settings, members or deletes a trip. Editor may change shared budget through the bounded RPC.
6. Each editor uploads a different private document. Neither the owner nor another member can list/download it. Viewer cannot upload. Uploader can manage their own files from Your account after membership removal. Incomplete uploads remain identifiable and removable. Direct Storage upload without a reservation and ready state without an object must fail. Global limit is ten documents per booking. Shared booking/trip deletion is blocked until uploaders remove their private documents. Storage objects must be removed before metadata.
7. Activity shows actor/record/action only; private filenames, references, content and notes are absent. Direct audit inserts/updates/deletes are forbidden.
8. While online, open Offline, choose a 10+ character passphrase and explicitly select optional documents (max three, 3 MB each). Download, turn networking off, open the reader, unlock and view plans/bookings/checklists/budget. Wrong passphrase/tampering must fail. No mutation UI/queue exists. Lock and background the reader: decrypted content disappears. Remove a copy and ensure it is gone. Inspect IndexedDB: only opaque IDs and encryption envelopes, never plaintext personal data. Service-worker cache contains only the public reader assets, never SSR pages/APIs/documents or Maps. Browser storage may be evicted; downloads need periodic refresh and are not backups. Revocation cannot erase existing offline copies.
9. Google profile menu, sign-out, narrow invite-only OAuth return path and existing Phase 1/2 flows still work at 375px and 1440px. Compare `/api/health` release/commit with Vercel logs; it is not a database readiness check.
